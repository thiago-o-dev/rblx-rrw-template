# Lightweight NPC System - Networking & Performance Optimization Plan

## 1. Executive Summary
This document defines the plan to transition the **Lightweight NPC** module from dynamic, custom byte-packing (`WriteBuffer.luau`, `ReadBuffer.luau`, `RemoteEvent`) to declarative, compile-time optimized networking via **Zap** (`rokit.toml`, `zap/`). It also specifies client rendering optimizations to achieve constant-time $O(1)$ interpolation and zero-reparenting spatial culling.

---

## 2. Zap Protocol Integration Architecture

### Proposed Zap Specification (`zap/npc-replication.zap`)
Instead of manual buffer offset increments and raw buffer passing over `RemoteEvent` instances, network packets will be generated by **Zap**:

```zap
opt toolchain = "rokit"

event InitialNpcState = {
    from: Server,
    type: Reliable,
    call: SingleAsync,
    data: struct {
        npcId: u16,
        model: Instance,
        hz: u8,
        position: Vector3,
        angle: f32,
    }
}

event NpcPositionBatch = {
    from: Server,
    type: Unreliable,
    call: SingleAsync,
    data: struct {
        serverTime: f64,
        positions: struct {
            npcId: u16,
            position: Vector3,
            angle: f16,
        }[]
    }
}

event NpcAnimationBatch = {
    from: Server,
    type: Reliable,
    call: SingleAsync,
    data: struct {
        serverTime: f64,
        animations: struct {
            npcId: u16,
            channel: u8,
            animIndex: u8,
        }[]
    }
}

event NpcCleanup = {
    from: Server,
    type: Reliable,
    call: SingleAsync,
    data: struct {
        npcId: u16,
    }
}
```

### Benefits of Zap Migration
1. **Performance**: Zap compiles native buffer packing/unpacking routines directly into Luau bytecode without table allocation overhead or custom bitwise Float16 math functions.
2. **Type Safety**: Automatic strict Luau typings generated under `src/server/Network/Generated/` and `src/shared/Network/Generated/`.
3. **Bandwidth Optimization**: Eliminates custom `MessageId` header bytes and struct alignment padding.

## 3. Client Render Loop & Memory Optimizations

### 1. $O(1)$ Timeline Ring Buffer Pruning
- **Current Problem**: `LightweightNpcsClientModule.luau` calls `table.remove(npcRecord.timeline, 1)` inside a `while` loop on every heartbeat step. Removing the first element from an array shifts all subsequent elements left, leading to $O(N)$ CPU performance penalty.
- **Optimization Solution**: Implement a fixed-capacity ring buffer with read/write head pointers, guaranteeing $O(1)$ insertions and lookups without memory reshuffling.

### 2. Zero-Reparenting Spatial Culling
- **Current Problem**: When an NPC timeline overruns or moves out of range, the client sets `npcRecord.instance.Parent = nil`. Upon re-entering range, it reparents the model back to `game.Workspace`. Reparenting atomic models forces Roblox to recalculate spatial trees, redraw textures, and rebuild rendering fast-clusters.
- **Optimization Solution**: Keep atomic models parented under a dedicated `Workspace.Npcs` container, and cull invisible or out-of-range NPCs by setting their CFrame off-screen (`CFrame.new(0, -9999, 0)`) or setting model transparency/scale.
